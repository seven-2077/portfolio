# 光线追踪器 · raytracer —— 纯 Python 光线追踪渲染器

零依赖、约 800 行核心代码，从一张白纸把「光是怎么走到你眼睛里的」完整算一遍。
图形学 × 物理光学的跨学科玩具：画面里每一个像素背后，都对应一条真实的物理定律。

玻璃球里的倒影、金属球上的天光、地面上的硬影子——没有用任何图形库，
全部由 `vec.py` 里的点乘、叉乘、反射、折射一行行推出来。

---

## 快速启动

Python 3.10+，Windows / Linux / macOS 通用，不装任何第三方包：

```bash
cd 02-projects/fun/raytracer

# 1) 跑测试：63 个用例，标准库 unittest
python -m unittest discover -s tests

# 2) 渲染三张图到 output/（约 2 分钟）
python demo.py

# 3) 自己调画质：更宽的图、更多采样、更深的反弹
python demo.py --scene classic --width 640 --samples 16 --depth 12
```

默认产物（双击即可用 Windows 照片查看器打开，手写 24bpp BMP）：

- `output/classic_480x270.bmp` —— 经典三球预览，480×270 · 4 spp
- `output/grid_480x270.bmp` —— 彩色玻璃球阵，480×270 · 4 spp
- `output/classic_hero_640x360.bmp` —— 高采样主图，640×360 · 8 spp

## 一条光线从相机穿过像素的旅程

### 第 1 步：像素不是「一个点」，是一扇小窗

480×270 的画面由 129,600 扇小窗拼成。如果每扇窗只从正中心发一条光线，
物体边缘会出现锯齿——那是「窗的边界被硬切」的痕迹。

所以每扇窗里随机取 4 个点（`spp`，samples per pixel），各发一条光线，
最后取平均。随机抖动 + 平均是蒙特卡洛积分的最简形态：
采样越多，越逼近「这扇窗真正收到的光」，锯齿被慢慢磨平。

### 第 2 步：针孔成像 —— 所有光线挤过一个点

相机没有透镜，只有一个点（`origin`）。在镜头前方 1 个单位处放一张「视口」，
垂直视场角 `vfov` 通过 `tan(vfov/2)` 决定视口的半高，宽高比再定出半宽。
视口上的归一化坐标 `(s, t) ∈ [0,1]²` 线性映射到视口位置，
视线方向 = 视口上的点 − 相机位置，归一化即得单位方向。

针孔的代价是没有景深——但这也意味着**天然全景深**，画面处处清晰。

### 第 3 步：在世界里寻找最近的碰撞

光线是参数方程 `P(t) = O + t·D`。把球的方程 `|P − C|² = r²` 代入，
得到关于 `t` 的一元二次方程：

- 判别式 < 0：射线擦身而过（miss）；
- = 0：恰好相切（正好擦到边缘的那个像素）；
- \> 0：两个根，取落在 `[t_min, t_max]` 里的**最近**那个——
  若近根太近（比如起点就在球表面），就试远根（从球内部出发的情况）。

平面更简单：一次除法 `t = ((P₀ − O) · n) / (D · n)`，分母≈ 0 就是平行。
交点处的法线永远翻转成「迎着射线」的一侧，同时记下 `front_face`——
玻璃内部二次入射时，必须知道现在是从哪侧穿出去的。

`HittableList` 负责调度：把每个物体问一遍，只留最近的一次命中，
并且每找到一次就收紧 `t_max`（后面的物体问得更省）。

### 第 4 步：撞上东西之后，光线分岔

这是渲染器的心脏（Whitted 风格）：

- **漫反射表面**：不再发新光线，直接按光照公式算完（下一节详述）；
- **金属**：按反射定律弹出 1 条新光线，携带反照率颜色，递归追踪；
- **玻璃**：按 Fresnel 比例分出 **2 条**新光线——反射 + 折射，
  各自带着自己的能量权重，递归追踪，颜色按权重叠加。

递归必须有终点：反弹上限（默认 8）用完直接返回黑色。
没有它，两面相对的镜子会让程序永远算下去——
`tests/test_renderer.py` 里专门造了一条「镜面隧道」来验证这个上限真的生效。

### 第 5 步：影子是一条额外的探测光线

对漫反射表面的每个光源，从交点沿光的方向再发一条射线问世界：
中途有任何**不透明**物体挡住，这盏灯的贡献就是 0 —— 硬阴影由此而来。
`n · l`（交点法线与光方向的夹角余弦）决定受光强弱：正对光的面亮，侧对的暗，
背对的（`n · l ≤ 0`）直接跳过。

玻璃被标记为「不挡光」（`casts_shadow = False`）：阴影射线穿过它继续往后探测，
所以玻璃球脚下不会出现一块死黑（代价是也没有焦散，见「已知局限」）。

### 第 6 步：没撞上任何东西，就去看天空

射线脱靶时，用它的仰角算背景：`t = 0.5 × (dir.y + 1)`，
在「地平线色」和「天顶色」之间线性插值。天空既是背景，也是画面里最亮的光源——
金属球上白花花的天光、玻璃球边缘的一圈亮斑都来自它。

### 第 7 步：平均、校正、落成文件

所有采样取平均，得到**线性 RGB**（正比于物理光量）。
但人眼对亮度的感知近似幂律，显示器也按 2.2 次幂响应——
所以写出前逐通道做 **sRGB（gamma）编码**，再裁剪到 0..255。
不做这步，画面中间调会全压成脏黑。

最后 `bmp.py` 手搓 54 字节文件头：`BM` 魔数、文件大小、40 字节信息头、
宽高位深、**自底向上**的行序、BGR 排列、每行补齐到 4 字节——
不依赖任何图像库，Windows 照片查看器直接打开。

## 四种材质模型 ↔ 四个物理事实

### Lambert 漫反射 —— 微面元的随机朝向

真实表面在微观上是无数朝向随机的小镜面（微面元）。它们把入射光弹向四面八方，
宏观上表现为出射亮度正比于 `cos θ`（**Lambert 余弦定律**），
且与观察角度无关——粉笔从正面看和侧面看一样亮，就是这个原因。

代码里就是一行：`颜色 = 反照率 ×（环境光 + Σ 光强 × max(0, n·l) × 阴影)`。
反照率 `albedo` 是「各波长的反射比例」：红球吸收绿蓝、只把红光弹回来，
所以同一盏白灯照上去，它只返回红色通道。

### 金属 —— 反射定律 + 微面元扰动

镜面反射遵守入射角等于反射角：`v' = v − 2(v·n)n`。
真实金属的自由电子让反射光带上金属的固有色（金偏黄，因为吸收蓝紫光），
代码用 `albedo` 表达这一点。

`roughness` 对应表面的微观起伏：不平整意味着每个微面元的法线随机倾斜，
反射方向因此在以镜面方向为中心的锥里抖动。
代码把反射方向叠加一个单位球内的随机向量再归一化——
这是物理渲染中 GGX 粗糙度模型的最简版本。抖进表面以下的光线被吸收（金属背面是黑的）。

### 玻璃 —— 折射、全反射、Fresnel 分账

- **折射**：折射率 `n = c / v_介质`，光在玻璃里变慢、波前拐弯，
  即 **Snell 定律** `n₁ sin θ₁ = n₂ sin θ₂`。正入射不偏折，斜入射向法线靠拢。
- **全内反射**：光从玻璃射向空气，入射角超过临界角
  `θ_c = arcsin(n₂/n₁) ≈ 41.8°`（n=1.5）时折射角无解，100% 能量弹回。
  光纤靠它把信号锁在纤芯里「弹着走」；钻石 n = 2.42 把临界角压到 24.4°，
  光在里面多弹几次才逃出去，所以才闪闪发光。代码里表现为 `refract()` 返回 `None`，
  玻璃只发反射光线。
- **Fresnel 分账**：反射和折射各拿多少能量？
  正入射只反射约 4%（所以迎面看玻璃几乎是透的），
  掠入射接近 100%（所以斜看窗户像面镜子）。
  精确公式对非偏振光取 Rs、Rp 两偏振的平均；
  **Schlick 近似**用 `r₀ + (1−r₀)(1−cos θ)⁵` 五次多项式逼近整条曲线，误差 < 0.05——
  两种实现都在 `materials.py` 里，用 `schlick=True/False` 切换，测试里逐点对过数。
- **体色**：折射光线乘上 `tint`，每穿越一次界面吸收一点——
  这是 Beer–Lambert 吸收定律的粗粒度版，彩色玻璃球阵的颜色就靠它累积。

### 天空 —— 瑞利散射的渐变替身

真实蓝天来自**瑞利散射**：大气分子尺寸远小于可见光波长，散射强度 ∝ 1/λ⁴。
蓝光（450nm）比红光（700nm）被散射强约 `(700/450)⁴ ≈ 5.8` 倍，
所以抬头是蓝天、看夕阳是红日。

本渲染器不做体积散射，用「仰角 → 线性渐变」近似这条物理链的**视觉结果**：
天顶偏蓝、地平偏白。它是发光背景，也是金属和玻璃反光里那片亮白的来源。

- `geometry.py`（112 行）—— 球/无限平面求交、`HitRecord`、最近命中调度与剪枝

- `tests/`（727 行，63 个用例）—— 向量/求交/材质/相机/BMP/渲染全覆盖

## 实测性能

纯 Python 单线程（Python 3.12，普通笔记本）：

- `classic` 480×270 @ 4 spp ≈ 19s（约 6.9 kpx/s）
- `grid` 480×270 @ 4 spp ≈ 46s（9 个球 + 玻璃双分支，最贵的场景）
- `classic_hero` 640×360 @ 8 spp ≈ 70s
- `python demo.py` 三张全出 ≈ 136s（2 分半以内）

想更快：调低 `--width` / `--samples`；想更美：反过来加。
`spp` 翻倍 ≈ 耗时翻倍，`width` 翻倍 ≈ 耗时 ×4。

## 已知局限（Whitted 渲染器的诚实清单）

- **没有焦散**：玻璃不投影，也聚不了光（玻璃杯底的亮斑需要路径追踪）；
- **没有色散**：彩虹边需要对 R/G/B 各追一次折射；
- **漫反射不反弹**：颜色不会「传染」给邻近物体（红墙旁的白地板不会泛红）；
- **硬阴影**：光源是一个点（方向光），没有半影柔和度；
- **线性叠加无色调映射**：极高亮处直接裁剪成白。

这些都是路线图上的正经升级项，不是 bug。

## English Summary

A dependency-free ray tracer written in pure Python (stdlib only, 3.10+,
~800 lines of core code). It renders 3D scenes of spheres and infinite planes
through a pinhole camera with multi-sample anti-aliasing, using a classic
Whitted-style pipeline: nearest-hit intersection, per-pixel recursion with a
bounce limit, shadow rays, and a vertical sky gradient.

Three material models map directly onto physical laws — Lambertian diffuse
(cosine law), metal (law of reflection with roughness jitter), and dielectric
glass (Snell refraction, total internal reflection, Fresnel/Schlick energy
splitting). Images are written as hand-rolled 24-bit BMP files with sRGB
(gamma) encoding, so no imaging library is required. The test suite
(63 unittest cases) covers vector math, intersection edge cases
(hit/miss/tangent), refraction numerics, BMP header round-trips, gamma
clamping, and verification of the recursion depth limit.

Run `python demo.py` to render three images in about two minutes.

## Roadmap

- **BVH 包围盒加速** —— 物体多了以后，`O(n)` 线性扫描会拖垮速度；
  把场景切成层级包围盒，求交变成 `O(log n)`，这是通往大场景的第一步
- **纹理** —— UV 参数化 + 棋盘格/图片采样，让地面不再是一块素色；
  BMP 读入器可以顺手复用现有的解码逻辑
- **三角形与 Möller–Trumbore 算法** —— 有了重心坐标插值法线，
  就能加载 OBJ 模型，从「数学玩具」变成「能渲染真实模型的引擎」
- （顺手项）`concurrent.futures` 多线程、薄透镜景深、
  路径追踪全局光照（焦散/色散/颜色传染）、PNG 输出（`zlib` 就在标准库里）
