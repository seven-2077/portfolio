# LearnLens · 研究计划书

一句话：**用数据科学方法研究一个真实考研人的备考过程** —— 自产数据讲故事、公开数据集验方法，交付「论文 + 诊断工具 + 内容素材」三轨成果。

状态：已立项（2026-11-04）· 第一步交付物 · 代码主体待 minidb / netlab 两项目收口后开工

---

## 1. 研究问题

### RQ1 · 时间投入与表现的滞后关系

每天的时长分配（科目 × 时段）如何关联次日与阶段性的自测表现？具体到：408 学了 3 小时的当天，次日章节自测的正确率是升是降还是无感 ——「学完即测」与「隔日回测」的效应差异，在个案纵向数据里能不能看到。

数据：study-timer 的 session 序列 × 自测成绩记录。方法：滞后互相关 + 分科目滚动窗口分析。成功标准：至少 8 周连续数据，能画出「投入-表现滞后热力图」。

### RQ2 · LLM 结构化干预对执行率的影响

「明日三件事」日报（母版已在 `05-ai/prompts/`）对次日实际完成率有无提升？这是可检验的：三件事的逐条回填标注构成因变量序列。

数据：日报的 checklist 字段 + 次日回看标注。方法：N-of-1 交替设计（有/无三件事的周交替，而非随机对照 —— 考研日常不允许真随机），配执行率时间序列的水平与趋势检验。成功标准：≥6 周交替数据，能给出效应方向与量级的个案结论。

### RQ3 · 基于日志文本的薄弱考点早期预警

把每日日志（Wiki inbox 的反思、错题备注）用 LLM 做考点语义标注（408 四门 + 数学的知识点词表对齐），看「薄弱考点热度序列」能否在自测暴露问题**之前**发出预警。

数据：反思日志文本 + 考点标注。方法：prompt 工程 + 抽样人工复核（10%，算 Cohen's κ 一致性）→ 热度序列 → 轻量预警规则或逻辑回归。成功标准：标注一致性 κ ≥ 0.7；预警与后续错题的时序吻合案例 ≥ 3 个。

## 2. 数据资产与数据字典

### 自产数据（独占，别人抄不走）

**session 时长**（已开始积累）—— 来源 `04-tools/study-timer/data/log.json`：`start`、`end`、`minutes`、`subject`（408/math/english/politics）、`note`。日粒度汇总为：科目时长、首末时段、连续天数。

**结构化日报** —— 来源 LLM Wiki inbox，按 `05-ai/prompts/每日学习日报母版.md` 产出。计划书新增两个**必须结构化的字段**（这是要改母版的地方）：`三件事[]` 带逐条 `status: pending|done|partial`，`自测[]` 带科目/章节/正确率。文本反思保留原样供 RQ3。

**自测成绩** —— 章节自测与真题的录入，需要一个最小录入工具（`learnlens` 代码的第一件交付物：命令行 30 秒录一条，低摩擦优先）。

**错题备注** —— 备考时随手写的错因文本，RQ3 的关键语料。

### 公开数据集（方法学验证用）

**EdNet**（KAIST，TOEFL 备考交互，千万级事件）—— 场景最贴：同样是「考试备考 + 交互行为」，用来验证「行为序列 → 表现预测」的管线有基线可比。

**OULAD**（Open University 学习分析数据集）—— VLE 点击流 + 最终成绩，学习分析领域的标准基准之一，LAK/EDM 审稿人熟悉，有说服力。

**ASSISTments** —— 数学教育交互与掌握度标注，若 RQ3 的「薄弱识别」要在更大样本上验证，从这里取。

分工原则一句话：**方法在公开集上验证（可复现、有基线），故事在自产数据上讲（独占、有深度）** —— 这样论文既有 external validity 的交代，又有别人做不出的个案细节。

## 3. 方法与技术路线

**标注管线**：考点词表先行（从 408 考纲 + 数学章节整理出结构化词表，作为 prompt 的锚点）→ LLM 逐条标注日志 → 10% 人工复核 → κ 达标才放行下游分析。8GB 显存约束：词表对齐型标注任务用量化 7B 级本地模型足够，量小也可分段调用 API 交叉验证 —— 这里正好和推理线的量化知识有交点，但不构成依赖。

**分析**：pandas / numpy 做序列与聚合；滞后效应用互相关；交替设计的执行率用水平-趋势分解；全程配图（matplotlib 出图，落盘 PNG/SVG 供论文与内容轨复用）。

**工程**：Python，`learnlens` 包（ingest → clean → annotate → analyze → report 五段管道）；数据落本地 JSON/CSV，可选导出；所有分析脚本一键可复现（锁定随机种子与环境说明）。硬件：8GB 显存 + 32GB 内存绰绰有余，本机全程可跑。

## 4. 成果三轨

**学术轨** —— 目标先低后高：arXiv 预印本（占位优先，2027-03 前挂出）→ 投 EDM / LAK 的 short paper 或 poster（截稿按往年 5 月预估，以官网为准）→ 有余力冲 AAAI-AIED 或国内 CSSCI（《电化教育研究》《现代教育技术》）。论文定位诚实写：**N-of-1 纵向案例研究 + 工具论文**，不吹普适性 —— 这个定位在教育数据挖掘会议是被接受且好中的类型。

**产品轨** —— `learnlens` CLI 与 HTML 报告：时长 × 表现散点、考点热度时间线、执行率仪表。第一用户是你自己，但 README 和截图按开源标准做，放 GitHub 当作品。

**内容轨** —— 「用数据科学备考」系列的素材工厂：每周的看板截图、滞后热力图、执行率曲线都是现成的差异化内容（对应之前分析的考研人设变现路径 —— 这条线的商业价值就放这里，不指望工具本身收钱）。

## 6. 风险与诚实边界

**N=1 的外部效度质疑** —— 靠公开数据集验证方法学回应；论文类型选 case study 而非 generalizable finding，审稿人按案例研究的标准评。

**数据量撑不起机器学习** —— 八周几百个 session 是纵向分析的量，不是深度学习的量。方法刻意选轻量（这反而是审稿友好与可复现友好）；模型只到逻辑回归级别，黑盒一律不碰。

**和备考的时间冲突** —— 每周 ≤5h 是硬预算，冲突时砍研究保备考，里程碑顺延不补课；11 月的启动任务已按「两楼收口后再动工」排他。

**LLM 标注的可靠性** —— κ 不达标就改 prompt 重标，不允许「感觉差不多」放行；标注样本小（每日几条），复核成本可控。
